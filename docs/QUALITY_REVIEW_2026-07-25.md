# Отчёт о ревью качества Avito Studio / Avito Bridge

Дата среза: 25 июля 2026 года.

Этот документ фиксирует границы, критерии и проверяемые результаты ревью двух
связанных репозиториев. Все числа ниже сняты после последнего изменения
production-кода и соответствуют исходникам, из которых собран итоговый EXE.

## Объём ревью

В проверку входят:

- весь production-код `avito-bridge/src`, его CLI и операционные скрипты;
- весь production-код `avito-studio/src`, Qt-интерфейс и PyInstaller spec;
- конфигурационные контракты четырёх профилей;
- автоматические тесты обоих репозиториев;
- сборка и запуск настоящего Windows EXE;
- безопасные read-only проверки внешних зависимостей.

Публикация живого фида, включение systemd service/timer, изменение товаров в
Avito и восстановление внешней БД в объём этого ревью не входят без отдельного
подтверждения владельца.

## Карта системы

```text
источник данных
    │
    ▼
avito-bridge: ingest → normalize → grouping → pricing → content → XML
    │                                                    │
    │ catalog_export                                     │ candidate validation
    ▼                                                    ▼
Avito Studio: просмотр/редактирование → сводка → подтверждение публикации
                                                         │
                                                         ▼
                                  профильный публичный фид на VPS → Avito
```

Bridge остаётся единственным владельцем правил формирования XML. Studio
управляет локальными изменениями и инициирует публикацию, но не дублирует
правила цены, группировки или идентификаторов.

## Профильные контракты

| Профиль | Источник | Группировка | Публикация из Studio |
| --- | --- | --- | --- |
| `conditioners` | read-only Oasis DB | серия | серверный кандидат, затем профильная атомарная замена |
| `wreaths` | RitualB2B | товар | серверный кандидат, отдельный публичный фид |
| `carver` | локальный XLSX | товар | локальная сборка, проверка, уникальный temp и атомарный `mv` |
| `appliances` | локальный XLS | товар | заблокирована; доступен только предпросмотр |

Для всех публикуемых профилей настроены минимальное число объявлений и предел
падения количества. Эти проверки дополняют, а не заменяют проверку XML.

## Учёт функций и тестов

Для итогового отчёта используются два воспроизводимых показателя:

1. production callable — каждый `FunctionDef` и `AsyncFunctionDef`, найденный
   через Python AST под `src/` обоих репозиториев, включая методы классов;
2. реальный тестовый случай — каждый node id, который возвращает
   `pytest --collect-only -q`.

Итоговое условие приёмки: число собранных тестовых случаев не меньше числа
production callable. Это не означает искусственного соответствия
«одна функция — один тест»: критичные публикационные функции должны иметь
несколько позитивных и негативных сценариев, а простые делегирующие методы
могут проверяться интеграционно.

| Репозиторий | Production callable | Собрано и пройдено тестов | Branch coverage |
| --- | ---: | ---: | ---: |
| `avito-bridge` (`src` + `scripts`) | 212 в 43 файлах | 347 | 88% |
| `avito-studio` (`src`) | 319 в 34 файлах | 407 | 88,329559% |
| **Итого** | **531** | **754** | отдельно по пакетам |

Условие `tests >= callables` выполнено с запасом **223 тестовых случая**.
Оба пакета имеют обязательный порог branch coverage 86%. Все 754 теста
исполняют production-код; `collect-only` использован только для
воспроизводимого подсчёта.

## Проверенные направления кода

### Bridge

- строгая проверка имён источников и режимов группировки;
- read-only и timeout-настройки подключения к БД;
- нормализация, дедупликация и профильные ручные товары;
- расчёт цены без накопления ошибок float;
- детерминированный выбор представителя серии без изменения входных объектов;
- стабильная идентичность объявления при смене доступного поставщика;
- экранирование XML, обязательные поля, уникальные `Id` и изображения;
- минимальное количество объявлений и защита от резкого падения;
- безопасная обработка изображений: MIME, размер, URL и пути;
- retry/close-контракт клиента Avito;
- безопасные режимы операционных скриптов;
- изолированная распаковка, lock, backup, атомарное продвижение и rollback
  профильного архива.

### Studio

- автономный старт без скрытого SSH-запроса;
- проверенный выбор корня Bridge и одноразовая установка встроенного шаблона;
- пользовательские настройки SSH с проверкой host, ключа и наличия OpenSSH;
- атомарная запись YAML, JSON, описаний и снимков;
- явная семантика «все / ничего / выбранные товары»;
- ручное и массовое редактирование с единым сохранением или полным откатом;
- точное сопоставление статусов по групповой идентичности объявления;
- фоновые workers и корректное закрытие окна во время операции;
- валидация CARVER-файла до его применения;
- отдельная блокировка публикации чернового профиля бытовой техники;
- диагностический rotating log и обработчик необработанных исключений;
- process smoke-test упакованного приложения.

## Матрица автоматической проверки

Финальный прогон включает следующие классы поведения:

| Область | Позитивный сценарий | Негативный/защитный сценарий |
| --- | --- | --- |
| Конфигурация | все допустимые профили загружаются | неизвестный source/grouping отклоняется |
| Источники | данные преобразуются в offers | timeout, неверный файл и пустой источник не публикуются |
| Нормализация | SKU/бренд/модель сохраняют контракт | дубликаты не создают повторные объявления |
| Цена | профильная формула даёт ожидаемую сумму | Decimal и границы округления не теряют копейки |
| Группировка | выбирается доступный представитель | порядок входа не меняет стабильный ID |
| XML | валидные объявления формируют `Ads` | пустые поля, фото и повторный `Id` отклоняются |
| Счётчики | допустимое изменение проходит | минимум и резкое падение блокируют продвижение |
| Архив Studio | разрешённые файлы попадают в stage | traversal, link/device и oversize отклоняются |
| Публикация | candidate проходит и заменяется атомарно | lock/ошибка копирования сохраняют прошлую версию |
| Клиент Avito | успешный ответ разбирается | retry исчерпывается, клиент всегда закрывается |
| Локальные настройки | изменения сохраняются атомарно | ошибка записи оставляет прежний файл |
| Ручные товары | create/edit/delete и bulk работают | отмена не оставляет частичных изменений |
| Статусы | совпадает нужный профиль и revision | чужой SKU/revision не помечается опубликованным |
| Qt workers | результат приходит в UI | ошибка и закрытие не оставляют работающий поток |
| EXE | окно запускается и создаёт workspace/log | запуск не требует сети или production-доступа |

## Реальная Windows-проверка

Итоговый файл:

- `dist/AvitoContentStudio.exe`, 69 801 714 байт;
- `FileVersion` и `ProductVersion`: `0.3.0.0`;
- SHA-256:
  `5EB55BA45C8D5A45827BABB75A016A39F1CDB2990B62246636C9E9083522E89A`.

Проверены два запуска настоящего PyInstaller EXE:

1. Чистый изолированный `LOCALAPPDATA`: exit code 0, установлен bundled
   workspace, присутствуют основной config, три дополнительных профильных
   YAML, описания и непустой rotating log.
2. Явный `AVITO_STUDIO_BRIDGE_ROOT`: exit code 0, лишний bundled workspace не
   создаётся и явно заданный путь остаётся авторитетным.

В обоих случаях встроенный UI self-check выполнился внутри настоящего Qt event
loop: главное окно показано, реестр всех четырёх профилей совпал, фоновые
операции самопроизвольно не стартовали, навигация «Обзор ↔ Каталог» работает,
поисковый фильтр устанавливается и очищается, а публикация `appliances`
остаётся заблокированной с указанной причиной. До и после обоих запусков
Windows `QSettings` имел одно и то же значение; smoke не заменил настройку
пользователя временной папкой.

Окно EXE отдельно обнаружено через Windows Accessibility как отвечающее окно
`Avito Content Studio 0.3.0`; его дерево элементов, подписи и disabled-состояния
прочитаны из живого процесса. Инъекция физического ввода в заблокированный
рабочий стол Windows была отклонена самой ОС, поэтому тот же набор кликов и
клавиатурных сценариев выполнен внутри Qt через process smoke и 407
`pytest-qt`/process тестов, а не через обход блокировки сессии.

Дополнительно на изолированном runtime с реальными поставщицкими файлами
запущено главное окно Studio и выполнены локальные профильные refresh:

- `appliances`: 599 строк каталога, 128 выбранных, поиск/сброс и числовая
  сортировка цены работают, публикация и сеть отключены;
- `carver`: 23 строки, 23 выбранных, поиск/сброс, сортировка, завершение worker
  и закрытие окна работают;
- отмена карточек, сохранение и rollback, bulk-изменения, настройки SSH,
  offline-cache и закрытие с активным worker проверены отдельными Qt-тестами.

Живая кнопка «Опубликовать» не нажималась: проверялся кандидат, а не изменение
production.

## Чистота репозиториев и supply chain

- реальные поставщицкие XLS/XLSX удалены из текущего дерева Bridge и добавлены
  в ignore; тесты создают синтетические книги;
- реальные Avito ID и upload URL заменены безопасными тестовыми значениями;
- `pip check` не нашёл конфликтов, `pip-audit` — известных уязвимостей;
- Ruff E9/F, `compileall`, Bandit medium/high и `git diff --check` проходят;
- EXE собирается только с чистого Bridge checkout и exact SHA из
  `bridge.lock`.

Старые поставщицкие бинарные файлы могут оставаться в прежних Git-коммитах.
История намеренно не переписывалась: force-push затронул бы существующие
ветки/клоны и требует отдельного явного решения владельца.

## Граница живой инфраструктуры

Read-only аудит 25 июля 2026 года показал:

- основной endpoint БД Oasis был недоступен для Bridge;
- systemd service и timer публикации на VPS были выключены;
- существование прежних XML на сервере не подтверждает актуальность их данных;
- код ревью не включал service/timer и не заменял живые фиды;
- проверки Avito и внешних каталогов выполняются read-only, если явно не
  подтверждена публикация.

Поэтому сквозной production-тест основного профиля нельзя считать пройденным
до восстановления БД. Это внешний операционный блокер, а не повод обходить
защитные проверки или публиковать устаревший кандидат.

## Оставшиеся операционные решения

Перед живым запуском владелец отдельно подтверждает:

- восстановленный read-only доступ к Oasis и свежесть источника;
- категории, наценки, фото и стратегию объединённого фида бытовой техники;
- целевые Avito account/feed для каждого профиля;
- актуальные секреты и SSH-ключ на целевой машине;
- результат preview/diff и количество объявлений конкретного кандидата;
- включение service/timer после ручного проверочного цикла.

Рекомендуемый порядок: восстановить источник → собрать read-only candidate →
проверить diff/XML/count → получить явное подтверждение → опубликовать один
профиль → проверить отчёт Avito → только затем решать вопрос о таймере.
