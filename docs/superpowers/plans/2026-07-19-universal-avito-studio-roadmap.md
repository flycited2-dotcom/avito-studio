# Universal Avito Studio Roadmap

**Goal:** Поэтапно заменить набор профильных YAML-инструментов единой системой импорта, редактирования, обогащения и публикации товаров без остановки текущего фида.

**Design:** `../specs/2026-07-19-universal-avito-studio-design.md`

## Порядок поставки

### Этап 1. Универсальные массовые операции

Расширить экспорт каталога данными каждой модели и её закупочной ценой. Добавить общий для всех профилей редактор публикации и цен, предварительную сводку, локальный снимок операции и возврат. Выполнить через UI отключение `XIGMA JETPRO` и `Ballu Aura`, затем скидку 5% на остальные включённые кондиционеры. Детальный план: `2026-07-19-universal-bulk-editor.md`.

**Приёмка:** операция применена локально через Avito Studio; тесты обоих репозиториев проходят; перед реальной публикацией показана точная сводка.

### Этап 2. Центральный каталог

Добавить в `avito-bridge` HTTP API, PostgreSQL-схему и миграции для профилей, товаров, предложений, переопределений, операций и публикаций. Добавить в Studio API-клиент и синхронизацию. Импортировать текущие YAML как начальную версию без изменения итогового XML.

**Приёмка:** два компьютера видят одинаковый черновик; повторная операция защищена номером версии; XML нового пути совпадает с контрольным для действующих профилей.

### Этап 3. Приёмная прайсов

Реализовать неизменяемое хранение файлов, парсеры XLSX/XLS/CSV и PDF/OCR, модель исходных записей, экран сопоставления, уровни уверенности и рецепты поставщиков. Первый шаблон подтверждается, последующий одинаковый формат проходит автоматически.

**Приёмка:** контрольные прайсы каждого формата воспроизводимо превращаются в одинаковые исходные записи; изменение колонок останавливает автоматический импорт.

### Этап 4. Универсальная карточка

Разделить товар и предложение поставщика, добавить точное и предлагаемое объединение дублей, динамические схемы категорий, индивидуальный и полный массовый редактор, слои `Авто`/`Ручное`/`Итог`, подборки и историю отмены.

**Приёмка:** один товар использует несколько предложений; любое изменение можно сбросить или отменить; несовместимое поле нельзя применить к другой категории.

### Этап 5. Контент и медиа

Добавить подтверждённые источники характеристик, очередь ИИ-задач, генерацию описаний без выдуманных фактов, медиаменеджер, извлечение изображений и интеграцию фотоагента с уникальным результатом по модели.

**Приёмка:** каждое сгенерированное утверждение связано с фактом; исходные изображения сохраняются; партия уникальных карточек проходит визуальную проверку.

### Этап 6. Конструктор профилей

Перенести категории, поля, ценовые, контентные и медиа-правила в серверные схемы. Создать интерфейс профилей и через него добавить стабилизаторы напряжения. Мигрировать четыре действующих направления.

**Приёмка:** профиль стабилизаторов создаётся без новой Python-формы; каждый действующий профиль собирает эквивалентный контрольный фид.

### Этап 7. Версионированная публикация

Перевести сборщик фида на итоговые карточки центрального каталога, добавить пакетную валидацию, предпросмотр, неизменяемые снимки, статусы Avito и восстановление предыдущей версии новой операцией.

**Приёмка:** публикация невозможна без подтверждения; сбой не меняет опубликованный статус; любой отправленный XML воспроизводится по снимку.

## Общие ворота качества

- Каждый этап начинается с теста текущего поведения и заканчивается сравнением контрольного фида.
- Миграция профиля выполняется отдельно и имеет выключатель возврата на старый путь.
- Ни один импорт, ИИ-процесс или массовая операция не запускает публикацию самостоятельно.
- Рабочие данные не коммитятся в Git.
- Независимые этапы получают отдельный подробный implementation plan и отдельную ветку.
